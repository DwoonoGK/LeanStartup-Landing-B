# 영농일지 옮김 · 가설 B 검증 랜딩

> 쓰던 영농일지를 옮겨드리고, 옮긴 기록을 필요할 때 다시 돌려드린다 — 베타 테스터(무료)를 모으는 랜딩 페이지

INSIDERS 린스타트업 · 검증 계획 **소재 B** (랜딩 → 신청). 이관 기능은 구현되어 있고, 이 페이지는 베타 테스터 신청을 받는다.

## 검증하는 가설

> 영농일지를 쓰는 농가 중 일부는, 쓰던 일지를 옮기면 그 기록으로 시기 알림·인증 서류 준비 같은 도움을 받는다는 제안에 연락처를 남긴다.
>
> (초기 문구는 "옮겨주고 다시 돌려받기"였고, 이후 "옮긴 기록을 데이터로 활용해 농작업을 돕는다"는 컨셉으로 바꿨다. 지표 정의는 그대로다.)

| 지표 | 정의 | 어디서 보나 |
| --- | --- | --- |
| 지표 1 | 랜딩 방문자 중 신청(문의)을 제출한 사람 수 | `summary` 탭 |
| 지표 2 | 신청자 중 우리 연락에 답해 **대화**한 사람 수 | `inquiries` 탭에 담당자가 `O` 표시 → `summary` 집계 |
| 지표 3 | 신청 1건당 광고비 | `summary` 탭에 광고비 입력 |

예산이 작으므로 비율보다 **"모수 몇 명 중 몇 명"** 으로 판단한다. 신청 건수만으로는 가설이 지지된다고 보지 않는다 — 지표 2가 질을 거른다.

## 페이지가 지키는 것

- 베타 테스트 중이며 **베타 테스터는 무료**라는 점을 밝힌다. 가격·인원·후기 같은, 근거 없는 숫자는 넣지 않는다.
- 폼 항목은 **연락처**, **지금 일지를 어떻게 쓰시나요? (종이 / 엑셀 / 앱 / 안 쓴다)** 두 개뿐이다. 사진·파일은 폼에서 받지 않는다.
- 팀 소개와, 수집하는 정보가 무엇인지 페이지에 적는다.
- 아직 없는 기능(시기 알림, 인증기관 제출, 작년·올해 비교)에는 **"베타에서 만드는 중"** 표시를 붙였다. 만들어지면 표시를 지우고, 계획을 바꾸면 문구를 고친다. 신청자와 연락할 때도 이 기능들이 아직 만드는 중이라고 말한다.
- 페이지에 쓴 기능 설명이 실제 서비스와 다르면 `index.html` 을 고친다.

## 구조

```
index.html          페이지 본문
config.js           ← 광고 켜기 전에 채울 설정 (폼 연결 주소, 연락 시점 문구)
assets/styles.css   디자인
assets/app.js       폼 검증 · 전송 · 이벤트 기록 · 스크롤 효과
apps-script/Code.gs 신청을 시트에 쌓고 메일로 알려주는 수신기
```

빌드 도구가 없는 정적 페이지다. Pretendard(글꼴)와 Lucide(아이콘)는 CDN에서 불러온다.

## 로컬에서 보기

```bash
python -m http.server 4173
```

`http://localhost:4173` 을 연다. `config.js` 의 `endpoint` 가 비어 있으면 **데모 모드**다. 화면 맨 위에 안내 띠가 뜨고, 신청은 어디에도 전송되지 않으며 브라우저 `localStorage` 의 `ilji_demo_log` 에만 남는다.

## 폼 연결 + 신청 메일 알림 (광고 켜기 전에 꼭)

신청이 오면 **구글 시트에 쌓이고, 메일이 온다.** Google Apps Script 로 만들었다 (구글 계정만 있으면 무료, 카드 불필요).

1. **메일을 받을 구글 계정**으로 로그인한 채 새 구글 시트를 만든다.
2. 메뉴 **확장 프로그램 → Apps Script** 를 열고, `apps-script/Code.gs` 내용을 붙여 넣는다.
3. 함수 선택에서 `setup` 을 골라 ▶ 실행한다 (권한 승인 필요 — 시트 접근, 메일 발송). `events` · `inquiries` · `summary` 탭이 생긴다.
4. 함수 선택에서 `testMail` 을 ▶ 실행해, 받은편지함에 시험 메일이 오는지 본다.
5. **배포 → 새 배포 → 유형: 웹 앱** — 실행 계정 `나`, 액세스 권한 `모든 사용자` 로 배포하고 **웹 앱 URL** 을 복사한다.
6. `config.js` 의 `endpoint` 에 그 URL을 붙여 넣고 커밋한다.
7. 페이지에서 시험 신청을 한 번 보내 `inquiries` 탭에 행이 생기고 메일이 오는지 확인한다. 그 행은 지운다.

**메일 받는 주소**는 기본으로 스크립트를 배포한 구글 계정이다. 다른 주소로 받으려면 Apps Script 의 **프로젝트 설정 → 스크립트 속성**에 `NOTIFY_EMAIL` 을 추가한다. (저장소가 공개라서 메일 주소를 코드에 적지 않았다.)

> ⚠️ `Code.gs` 는 이 저장소에서 실제 시트로 시험하지 못했다. 4번·7번 확인을 꼭 한다.
> 메일은 하루 약 100통까지(개인 구글 계정 기준) 보낼 수 있고, 한도를 넘어도 시트에는 계속 쌓인다.
> 웹 앱 URL을 아는 사람은 누구나 행을 추가할 수 있다. 페이지 소스에 URL이 보이므로, 스팸이 들어오면 새로 배포해 URL을 바꾼다.

### 시트가 받는 것

| 탭 | 내용 |
| --- | --- |
| `events` | `landing_view`(방문) · `cta_click`(버튼 클릭) · `form_start`(폼 첫 입력). 이름 없는 방문자 ID만 있다. |
| `inquiries` | 접수시각 · src · 연락처 · 일지 방식. 뒤쪽 `연락 시도(O)` · `답변함(O)` · `대화함(O)` · `메모` 는 **담당자가 직접** 채운다. |
| `summary` | 방문자 · 신청 · 답변 · 대화 · 신청 1건당 광고비 자동 계산 (광고비 칸만 직접 입력) |

## 광고 링크

광고 소재 B의 링크에는 반드시 `src=B` 를 붙인다. `summary` 가 `src=B` 만 집계한다.

```
https://<배포 주소>/?src=B
```

광고 플랫폼의 UTM(`utm_source`, `utm_medium`, `utm_campaign`)도 같이 붙이면 시트에 기록된다.

## 배포

정적 파일이라 어디에나 올릴 수 있다 (GitHub Pages, Netlify, Vercel 등).

- GitHub Pages: 저장소 **Settings → Pages → Branch: `main` / root**.
- **폼 연결(위)을 끝내기 전에는 배포하지 않는다.** `endpoint` 가 비어 있으면 신청이 사라지고, 페이지 위에 데모 안내 띠가 보인다.
- 연락처는 시트에만 저장되고 저장소에는 들어가지 않는다. `config.js` 의 `endpoint` 는 페이지 소스에 노출된다.
