# 영농일지 옮김 · 가설 B 검증 랜딩

> 쓰던 영농일지를 옮겨드리고, 옮긴 기록을 필요할 때 다시 돌려드린다 — 이 제안에 농가가 연락처를 남기는지 확인하는 랜딩 페이지

INSIDERS 린스타트업 · [검증 계획: 소재 A 음성 기록 · 소재 B 랜딩 문의] 중 **소재 B**

**이 페이지의 목적은 서비스를 보여주는 게 아니라, 광고를 누른 사람이 문의를 남기는지 숫자로 보는 것입니다.**
이관 기능은 만들지 않았습니다. 문의가 오면 우리가 직접 연락합니다.

---

## 검증하는 가설

> 영농일지를 쓰는 농가 중 일부는, 쓰던 일지를 옮겨주고 다시 돌려받는 제안에 연락처를 남긴다.

| 지표 | 정의 | 어디서 보나 |
| --- | --- | --- |
| 지표 1 | 랜딩 방문자 중 문의를 제출한 사람 수 | `summary` 탭 |
| 지표 2 | 문의자 중 우리 연락에 답해 **대화**한 사람 수 | `inquiries` 탭에 담당자가 `O` 표시 → `summary` 집계 |
| 지표 3 | 문의 1건당 광고비 | `summary` 탭에 광고비 입력 |

예산이 작으므로 비율보다 **"모수 몇 명 중 몇 명"** 으로 판단합니다. 문의 건수만으로는 가설이 지지된다고 보지 않습니다 — 지표 2가 문의의 질을 거르는 장치입니다.

## 페이지가 지키는 약속

- "개발 중인 시범 서비스"임을 맨 위와 중간에 밝힌다. 있는 기능처럼 쓰지 않는다.
- 폼 항목은 **연락처**, **지금 일지를 어떻게 쓰시나요? (종이 / 엑셀 / 앱 / 안 쓴다)** 두 개뿐이다.
- 사진은 폼에서 받지 않는다. 대화가 된 뒤에 그 자리에서 묻는다.
- 팀 소개와, 수집하는 정보가 무엇인지 페이지에 적는다.

## 구조

```
index.html          페이지 본문
config.js           ← 광고 켜기 전에 채울 설정 (폼 연결 주소, 연락 시점 문구)
assets/styles.css   디자인
assets/app.js       폼 검증 · 전송 · 이벤트 기록 · 스크롤 효과
apps-script/Code.gs 구글 시트로 문의·방문을 받는 수신기
```

빌드 도구가 없는 정적 페이지입니다. Pretendard(글꼴)와 Lucide(아이콘)는 CDN에서 불러옵니다.

## 로컬에서 보기

```bash
python -m http.server 4173
```

`http://localhost:4173` 을 엽니다. `config.js` 의 `endpoint` 가 비어 있으면 **데모 모드**로 동작합니다. 화면 맨 위에 안내 띠가 뜨고, 문의는 어디에도 전송되지 않으며 브라우저 `localStorage` 의 `ilji_demo_log` 에만 남습니다.

## 폼 연결 (광고 켜기 전에 꼭)

문의 폼 도구는 아직 정해지지 않았습니다. 기본 구현은 **구글 시트 + Apps Script** 입니다 (계정만 있으면 무료, 카드 불필요).

1. 새 구글 시트를 만든다.
2. 메뉴 **확장 프로그램 → Apps Script** 를 열고, `apps-script/Code.gs` 내용을 붙여 넣는다.
3. 함수 선택에서 `setup` 을 골라 ▶ 실행한다 (권한 승인 필요). `events` · `inquiries` · `summary` 탭이 생긴다.
4. **배포 → 새 배포 → 유형: 웹 앱** — 실행 계정 `나`, 액세스 권한 `모든 사용자` 로 배포하고 **웹 앱 URL** 을 복사한다.
5. `config.js` 의 `endpoint` 에 그 URL을 붙여 넣는다.
6. 페이지에서 시험 문의를 한 번 보내 `inquiries` 탭에 행이 생기는지 확인하고, 그 행은 지운다.

> ⚠️ `Code.gs` 는 이 저장소에서 실제 시트로 시험하지 못했습니다. 6번 확인을 꼭 하세요.
> 웹 앱 URL을 아는 사람은 누구나 행을 추가할 수 있으므로 URL을 공개 게시판에 올리지 마세요. (페이지 소스에는 보입니다.)

### 시트가 받는 것

| 탭 | 내용 |
| --- | --- |
| `events` | `landing_view`(방문) · `cta_click`(버튼 클릭) · `form_start`(폼 첫 입력). 이름 없는 방문자 ID만 있다. |
| `inquiries` | 접수시각 · src · 연락처 · 일지 방식. 뒤쪽 `연락 시도(O)` · `답변함(O)` · `대화함(O)` · `메모` 는 **담당자가 직접** 채운다. |
| `summary` | 방문자 · 문의 · 답변 · 대화 · 문의 1건당 광고비 자동 계산 (광고비 칸만 직접 입력) |

## 광고 링크

광고 소재 B의 링크에는 반드시 `src=B` 를 붙입니다. `summary` 가 `src=B` 만 집계합니다.

```
https://<배포 주소>/?src=B
```

광고 플랫폼의 UTM(`utm_source`, `utm_medium`, `utm_campaign`)도 같이 붙이면 시트에 기록됩니다.

## 배포

정적 파일이라 어디에나 올릴 수 있습니다 (GitHub Pages, Netlify, Vercel 등).

- GitHub Pages: 저장소 **Settings → Pages → Branch: `main` / root**. (무료 계정은 공개 저장소여야 한다.)
- 연락처는 시트에만 저장되고 저장소에는 들어가지 않는다. 다만 `config.js` 의 `endpoint` 는 페이지 소스에 노출된다.
